# Guideline: Creating Good Figures

## General principles

- A figure should be understandable without reading the surrounding text — the caption carries the explanation.
- Every figure must be referenced in the text before it appears.
- Prefer showing results visually over describing them in prose.
- A figure tells a story: identify the single key takeaway before you design the visual.

## File format

- Always save as **PDF** from matplotlib — vector format, scales perfectly in print and screen.
- Also save a **PNG** copy at 150–200 dpi alongside the PDF — this allows Claude Code to read the figure visually and give feedback on layout, legibility, and storytelling before it is included in the paper.
- Output goes to `paper/figures/`, generated by scripts in `assets/python/`.
- Never manually edit a figure file — always regenerate from the script.

## Review loop (when generating figures with Claude Code)

After running the generation script, Claude should:

1. Read the PNG with the Read tool to visually inspect the figure.
2. Check it against the checklist below (legibility, grayscale, takeaway, clutter).
3. Revise the script if any issue is found, regenerate, and re-inspect.
4. Repeat until the figure passes all checklist items.

## Typography

- Match the font family of the paper (typically serif for academic venues).
- Axis labels, tick labels, and annotations should be readable at the final print size — always check in the compiled PDF, not just the script output.
- Do not add a figure title in the plot — the LaTeX caption serves that purpose.

## Color and accessibility

- Ensure the figure is readable in **grayscale** — use linestyles (`-`, `--`, `-.`, `:`) in addition to colors, not instead of them.
- Avoid red/green combinations — colorblind unfriendly.

## Captions

- Place the caption **below** the figure.
- The caption should describe what the figure shows and what to take away — not just a label like "Results."
- A good caption is self-contained: a reader should understand the figure without reading the body text.

## Data storytelling

When a figure is part of a broader argument or results narrative, follow the **5D process**:

1. **Define** — state the key takeaway before designing the figure. What single insight should the reader walk away with?
2. **Draft** — sketch the storyline: what data supports the takeaway, and in what order?
3. **Display** — choose a chart type that matches the comparison (trend → line, composition → bar/pie, relationship → scatter).
4. **Declutter** — remove every element that does not support the takeaway: unnecessary gridlines, redundant labels, decorative ink.
5. **Direct** — guide the reader's eye to the key insight using color, annotation, or position. The takeaway should be visually obvious.

The formula: **Data Story = Visuals + Data + Narrative → Key Takeaway**

A figure is a weak data story if it presents data without a narrative or takeaway direction.

## Checklist before including a figure

- [ ] Is it referenced in the text?
- [ ] Is the caption self-explanatory?
- [ ] Are fonts readable at print size?
- [ ] Does it work in grayscale?
- [ ] Is the script in `assets/python/` committed so the figure can be regenerated?
- [ ] Has the PNG been visually inspected (by Claude Code or a human) before inclusion?
- [ ] Is there a single, clear takeaway the figure communicates?
- [ ] Has unnecessary ink been removed (decluttered)?
